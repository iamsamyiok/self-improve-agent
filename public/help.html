1. 五分钟上手

第一步：安装

npm install

要求 Node.js 18 或更高版本。项目运行时尽量只使用 Node.js 内置能力，不依赖庞大的运行时框架。

第二步：启动

npm start

打开终端显示的本地地址，在网页中完成内层模型配置。内层 Agent 使用 OpenAI-compatible API；外层 Meta-Agent 使用 OpenCode CLI。

第三步：直接聊天

例如：

读取项目里的 README.md，告诉我这个项目是做什么的，并指出最值得改进的地方。

你不用告诉 Agent “请开始进化”。先正常完成真实任务即可。

第一次为什么不会立刻进化？

系统默认至少积累 3 个成功完成的 Benchmark 才启动第一次正式实验。两个任务不足以形成可靠的 A/B 样本。第三个成功任务完成后，后台会异步启动 Evolution；实验本身可能需要一些时间。

2. 整体架构

你提出任务
→
Inner Agent真正干活
→
Experience留下可复盘经验
→
Meta-Agent寻找改进假设
→
Evolution Lab隔离实验
→
新版本通过才升级

Inner Agent 是产品本身：理解用户、调用工具、读取/修改文件、验证结果并交付。

Meta-Agent（Outer Agent） 是后台的“改进大脑”：它不负责日常替用户完成任务，而是观察历史任务，提出一个最小、可验证的变化。

Evolution Engine 是实验与质量闸门：它不相信“看起来更好”，而是让原版本和候选版本重新完成同一批任务。

3. 一次任务到底发生什么

  1. 理解任务：提取任务目标、验收条件和预期交付物。
  2. Recall：从短期、长期、归档和语义记忆中找相关经验。
  3. 执行：Inner Agent 根据需要调用插件，例如 read、write、edit、bash、search、verify。
  4. 验证：任务结束前检查关键要求是否完成；缺失时自动返修。
  5. 交付：把最终结果返回给用户。
  6. 归档：成功任务会自动进入经验与 Benchmark 系统，供未来实验重放。

4. 什么时候会进化？

用户行为后台行为进化史
第 1 个成功任务保存 Benchmark 1没有正式实验记录，正常
第 2 个成功任务保存 Benchmark 2继续收集样本
第 3 个成功任务保存 Benchmark 3，自动启动 Evolution实验完成后出现第一条记录
之后继续使用持续增加样本，并在后台寻找新的改进机会按时间倒序记录每次实验

默认 自动 Evolution 已开启。无需设置 DUAL_AGENT_AUTO_EVOLVE=1；只有设置为 0 才关闭。

默认 自动 Promote 也开启。只有候选版本通过实验和 Regression Guard 才会升级。

“第三个任务到了，但仍然没有进化史”怎么办？
  1. 确认第三个任务确实正常完成，而不是中断/报错。
  2. 打开“🧬 进化史”，看顶部的 Benchmark 进度。
  3. 后台实验需要调用 OpenCode Meta-Agent。如果没有检测到外层引擎，系统不会伪造一条成功进化记录。
  4. 可以执行 hwj-agent evolve 手动触发并查看终端错误。

5. 怎么看懂“🧬 进化史”

进化史按时间倒序显示最新实验。它不是开发者 JSON 日志，而是面向用户的变化说明。

页面内容用户应该怎么理解
发生了什么这次具体改变了哪一部分，例如“调整记忆召回策略”。
为什么变化Agent 从过去任务中观察到了什么问题。
Agent 的假设它认为哪一种小改动可能解决问题。
实际结果候选版本重新完成历史任务后，相对原版本提高了多少、赢了多少。
最后怎么处理通过并自动升级，或者没有证明更好而继续使用原版本。

例如一条记录可以被理解成：

为什么改？
→ 最近几个任务的历史经验召回不足。

改了什么？
→ 调整 memory recall 策略。

怎么证明？
→ 用同一批历史任务跑 Baseline 和 Candidate。

结果？
→ Candidate 平均 +8.4%，12 个任务中赢了 10 个。

最后？
→ 通过 Regression Guard，自动升级到下一版本。

6. Self-Improving Loop 完整过程

阶段作用
Observe观察真实任务、工具表现、交付结果和历史经验。
Diagnose寻找重复失败、低效步骤或能力瓶颈。
Hypothesize提出一个可以被实验否证的改进假设。
Mutate只做尽量小的单变量变化，可作用于插件、提示、Skill、策略或记忆召回。
Sandbox候选变化在隔离目录/独立进程中运行，不直接污染生产。
A/B同一批 Benchmark 分别运行 Baseline 和 Candidate。
Evaluate结合任务结果、产出文件、工具过程指标和可用的 LLM Judge 进行评分。
Regression Guard检查平均提升、胜率和严重回归，避免“平均看起来好但某类任务坏掉”。
Promote只有通过质量闸门的候选版本才进入下一版本。
Learn成功与失败的实验都会写入 Evolution Experience，供下一轮参考。
核心原则：“修改”不等于“进化”。只有“修改 → 实验 → 证明更好 → 采用”才算一次真正的进化。

7. 记忆系统

Agent 不只是依赖当前聊天窗口。项目提供多层经验检索：

  • 短期记忆：当前工作上下文中的近期信息。
  • 长期记忆：稳定、值得长期保留的经验。
  • 任务归档：用户任务与最终交付，可作为未来任务的经验来源。
  • 关键词/BM25：适合明确词汇和任务名称。
  • Embedding：适合语义相似但措辞不同的历史经验。
  • RRF：将不同检索结果进行融合排序。

记忆的意义不是“把所有历史都塞给模型”，而是让 Agent 在当前任务需要时找到少量真正相关的经验。

8. 插件系统

插件是 Agent 的“手”。每个插件通常承担一个清晰职责，并向模型声明参数 Schema 和执行入口。

类别典型能力
文件read / write / edit
命令bash / shell 类任务
搜索本地或配置好的搜索能力
验证verify 等质量检查
记忆recall / archive 等经验操作

日常使用不需要管理插件。点击顶部 🧩 插件 才进入插件管理页面。插件的源码编辑、导入、AI 修复等属于低频维护功能。

9. Skills 技能系统

插件解决“能做什么”，Skill 更接近“应该怎么做”。Skill 可以提供某类任务的工作方法、约束、检查清单和最佳实践。

渐进式加载：系统启动时只把「名称 + 描述」清单注入上下文（每个约 100 token），Agent 判断任务与某技能匹配时才读取全文——省 token 又不失专业性。目录型技能还会自动生成捆绑资源清单（脚本、模板、参考文件），照抄路径即可使用。

技能预取（v3.4.0）：任务开始时系统会自动把你的任务描述与全部技能库匹配（支持中英文桥接，例如「深度调研」能匹配到英文描述的 research 类技能），命中即主动提示 Agent「先读技能全文、按其步骤执行」。清单按字母排序最多展示 40 个，预取匹配覆盖全量，排序靠后不会被遗漏。

Self-Improvement 可以针对 Skill 做实验。例如发现某类任务经常遗漏最终验证，可以提出一个更强的验证 Skill，然后用历史任务比较效果。

10. 强化处理与外部学习

强化处理（Reinforce）——自己的错题自己练

任务失败、返修两次以上、被中断或被撤回时，系统会自动把这类任务加入补练队列。空闲时（不影响你正常使用）它会：

  1. 归因：分析失败根因（工具误用 / 知识缺口 / 规划缺陷 / 验收误读 / 外部依赖）。
  2. 补练：在隔离沙箱中重做同一任务，直到过关（用客观断言或 LLM 评审双通道核验）。
  3. 沉淀：把有效经验写成简报——操作步骤类沉淀为技能（低风险直接入库），行为规则类进入基因池走 A/B 实验验证后才生效。

同一类根因反复升级解决不了时，系统会自动聚类并在下一次进化实验的视野里标注，推动结构性修复。你可以在「🧬 进化史」抽屉的强化处理区块查看队列、补练进度和沉淀结果，也可以点击「立即补练」。

外部学习（Scout）——向社区偷师

系统空闲时还会扫描 GitHub 上的高星 Agent 项目（每日有预算上限），从它们的 README 中提炼值得借鉴的机制：

借鉴类型处理方式
知识 / 方法论（如调试流程、写作规范）硬校验（必须引用真实工具、字数达标）后直接入库为技能
行为 / 策略（如检索排序、任务拆分方式）进入基因池，走 A/B 实验证明有效后才启用

原则与自进化一致：先学习，再验证，后启用。外部经验同样不享有免检特权。除自动调度外，你也可以随时点击左侧菜单的 GitHub 学习 手动触发一次（任务或实验进行中时会提示顺延）。

什么时候运行？

两者都在系统空闲时（没有任务执行、没有进化实验）自动运行，每 30 分钟检查一次，优先级为「补练自己的错题 > 学习别人的经验」，各自每天最多处理 5 个，不会影响正常任务。

11. 质量、安全与回滚

为什么 Candidate 不直接覆盖当前版本？

因为 Agent 很容易产生“局部变好、整体变坏”的修改。Candidate 会在实验目录中运行，生产环境保持不变。

Regression Guard

默认门槛包括最低样本数、平均提升、胜率以及严重回归限制。具体参数可通过环境变量调整。

回滚

插件类 Promote 复用快照/预检/热加载管线；出现问题可以回滚到之前的状态。策略类进化则以 Evolution State 的版本方式保存。

安全边界：自动进化的目标是让 Agent 在已有能力边界内更稳定、更高效，而不是让它无条件获得系统权限。涉及高风险生产环境时，应关闭自动 Promote，并增加人工 Gate、代码审查或外部 CI。

12. 界面说明

左侧菜单按「任务执行 → 自我改进 → 成长指标」三个层次组织：

分组菜单项用途日常频率
任务执行对话与 Inner Agent 完成真实工作每天
执行过程实时工作流审计：工具调用序列、执行事件与 token 计量需要时
智能体快照一屏查看当前执行智能体的构成：版本与模型、工作流水线说明、当前会话上下文占用、完整系统提示词、插件清单（含来源与状态）、技能清单与进化状态需要时
自我改进进化中心进化实验、版本历史、健康分与强化处理明细偶尔
GitHub 学习手动触发一次外部学习：扫描高星 Agent 项目、提炼可借鉴机制入库（技能硬校验 / 行为基因走 A/B）低频
帮助查看本说明需要时
成长指标样本 / 实验进化样本量与实验次数的实时快照顺带看

版本与更新：侧栏底部显示当前程序版本号，点击「检查更新」会对比 GitHub 最新 release——已是最新则提示，有新版本会自动打开发布页供下载升级。

智能体快照里能看什么：它是「透明化」入口。你可以看到智能体每次任务遵循的五步流水线（预取 → 规划 → 执行 → 核验 → 沉淀）、当前上下文占了多少预算、发给模型的系统提示词全文、它在用哪些插件和技能、进化到第几版。看完你就知道「它为什么会那样干活」。

13. 配置与环境变量

变量作用默认
DUAL_AGENT_AUTO_EVOLVE是否自动触发 Evolution；设为 0 关闭开启
DUAL_AGENT_AUTO_PROMOTE实验通过后是否自动升级；设为 0 关闭开启
DUAL_AGENT_EVOLUTION_MIN_CASES第一次正式实验所需最少 Benchmark3
DUAL_AGENT_EVOLUTION_MAX_CASES最多保留/使用的 Benchmark 数量50
DUAL_AGENT_EVOLUTION_MIN_DELTA最低平均提升阈值0.03
DUAL_AGENT_EVOLUTION_MIN_WIN_RATE最低胜率0.60
DUAL_AGENT_EVOLUTION_MAX_REGRESSION允许的单案例严重回归阈值0.08
DUAL_AGENT_MOCK演示/测试模式关闭
DUAL_AGENT_OPENCODE_CMD指定外层 OpenCode 命令自动检测

生产环境建议先保持默认设置。若希望完全停止自动自我修改，可使用：

DUAL_AGENT_AUTO_EVOLVE=0
DUAL_AGENT_AUTO_PROMOTE=0

14. 命令行

# 启动 Web
npm start

# 执行一次任务
hwj-agent run "分析 README.md"

# 手动运行一次 Evolution
hwj-agent evolve

# 手动 Evolution，并允许通过门槛后 Promote
hwj-agent evolve --promote

# 安静执行
node hwj/hwj.js --script "读取 hello.txt" --quiet

Web UI 自动进化和命令行 Evolution 使用同一个 Evolution Engine。

15. 数据保存在哪里

.data/
├── evolution/
│   ├── benchmarks/       # 可重放任务样本
│   ├── experiments/      # 每次实验及 A/B 结果
│   ├── state.json        # 当前进化版本/状态
│   ├── leaderboard.json  # 实验表现排名
│   └── experience.jsonl  # 进化经验
├── config.json            # 本地配置
└── ...                    # 运行时记忆、审计等

workspaces/
└── default/               # 用户工作区

这些运行数据不应该进入源码发布包。清洁源码 ZIP 不包含 node_modules、.data、工作区运行数据和 .git。

16. 常见问题

Q：我聊天两次，为什么没有进化？

A：正常。默认至少需要 3 个成功 Benchmark。系统宁可多收集一点真实任务，也不根据两个样本乱改 Agent。

Q：第三个任务完成后是不是一定升级？

A：不是。第三个任务只是允许启动实验。Meta-Agent 可能认为没有可靠改进点，或者 Candidate 没有通过 A/B 和 Regression Guard。此时原版本继续工作。

Q：进化会不会直接改坏我的程序？

A：Candidate 先在隔离实验环境中验证；只有通过质量闸门才 Promote。插件 Promote 还会经过现有的快照/预检/热加载管线。

Q：为什么进化史还是空的？

A：最常见原因是 Benchmark 尚未达到最低数量，或者外层 OpenCode 没有配置/无法启动。进化史只记录正式实验，不会为了让页面“有数据”而伪造成功。

Q：可以关闭自动进化吗？

A：可以：DUAL_AGENT_AUTO_EVOLVE=0。也可以只关闭自动升级：DUAL_AGENT_AUTO_PROMOTE=0。

Q：我能手动实验吗？

A：可以运行 hwj-agent evolve。手动和自动使用同一套 Benchmark、A/B、Evaluator 和 Regression Guard。

Q：插件是不是每次都要我自己选？

A：不需要。插件是 Agent 的工具层，正常任务由 Agent 自己选择。用户只有在维护系统时才进入 🧩 插件。

Q：我想知道智能体到底是怎么工作的，去哪里看？

A：左侧菜单「智能体快照」。它展示当前智能体的版本与模型、每次任务的五步工作流水线、系统提示词全文、插件与技能清单、进化状态和当前上下文占用——看完就能理解它的行为逻辑。

Q：程序怎么更新？

A：侧栏底部有版本号和「检查更新」按钮。点击后会对比 GitHub 最新 release，有新版本时自动打开发布页，下载新版本覆盖安装即可；运行数据（.data、workspaces）不受影响。

Q：强化处理和外部学习会干扰我正常使用吗？

A：不会。两者只在系统空闲时运行（没有任务、没有进化实验），每天各有处理上限，被中断也不会影响当前任务。你可以在进化史抽屉里随时查看或手动触发。

Q：这个项目和普通 Agent 有什么根本区别？

A：普通 Agent 的循环通常是“任务 → 执行 → 结果”。这里增加了第二个闭环：“真实任务 → 经验 → 假设 → 候选 → 实验 → 评价 → 晋级/丢弃”，让系统可以基于真实使用结果持续寻找下一版本。

如果你继续开发，建议保持一个原则：不要把“进化逻辑”和“用户日常操作”混在一起。用户只消费结果；系统自己负责观察、实验、验证和版本管理。

最后总结：把 HWJ Agent 想成一个会工作的数字员工。你给它任务，它负责完成；它把完成过的任务留下来；当积累了足够证据，它会在后台提出一个小改动并自己做实验；实验真的证明变好，它才升级；失败则继续使用旧版本。你只需要偶尔打开“🧬 进化史”，看看它最近学会了什么。
