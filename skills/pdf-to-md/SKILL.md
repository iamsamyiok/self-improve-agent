# PDF to Markdown 转换

把 PDF 转成高质量 Markdown。脚本负责批量提取与规则化结构，你（Agent）负责脚本做不好的润色：不规则表格、多栏版面、层级校正。

## 执行步骤（必须按序）

### 第 1 步：确认输入

用 read 插件确认 PDF 文件存在（路径错误时 read 会报错，据实转告用户，不要臆造内容）。

### 第 2 步：运行转换脚本

用 bash 插件执行（脚本绝对路径见 get 返回的捆绑资源清单中 `→` 后面的路径）：

```bash
python3 <pdf_to_md.py 的绝对路径> <输入.pdf> <输出.md>
```

输出路径规则：用户指定了就用指定的；否则与 PDF 同名 `.md`，存到工作区。

脚本 stdout 会给出统计：引擎（pdftotext/pypdf）、页数、标题/列表/表格计数、疑似表格待润色数、剔除的页眉脚字符数。

**退出码**：0 成功；2 文件不存在或提取失败；3 几乎无文本（扫描版 PDF，需 OCR）——遇到 3 时向用户说明该 PDF 是扫描版/图片型，本技能无法处理，建议提供文字版或先用 OCR 工具。

### 第 3 步：质检输出

用 read 插件读取输出的 .md，重点核对：

1. 标题层级：`#` 深度是否与原文档层级一致（文档主标题应为 `#`，章节降一级）
2. 统计中「疑似表格待润色」> 0 时：脚本保留了多空格对齐的原文块（避免错列风险），你必须按原文人工转成 Markdown 表格（`| 列 | 列 |` + `|---|---|`），逐行核对列归属
3. 段落完整性：跨页段落是否正确合并、连字符断词是否拼回
4. 乱码/错序：多栏 PDF 常出现左右栏文本交错，发现时按语义重排

### 第 4 步：修正与交付

质检发现的问题用 edit/write 插件直接修正 .md，然后向用户报告：

- 输出文件路径
- 关键统计（页数、标题/列表/表格数、润色了什么）
- 无法处理的部分（如图片、复杂公式）如实说明

## 约束

- 禁止臆造 PDF 中不存在的内容；脚本提取不到就报告提取不到
- 一次转换失败先看 stderr（如缺 pypdf 时 `pip3 install --break-system-packages pypdf` 可修复依赖；pdftotext 缺失时脚本自动回退 pypdf）
- 大 PDF（>100 页）转换后 read 分段抽查（offset/limit），不要一次全读
